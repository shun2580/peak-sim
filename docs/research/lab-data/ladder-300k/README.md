- `s-1.output.txt` to `s-5.output.txt`: the output of each scenario. `s-1.not-started-0900.output.txt`: the first start of s-1 at 08:59:57, which ended with exit 2 at 09:00:11 before any load because `targets-300000.json` was missing; `targets-300000.output.txt` is the run of `bin/targets` that made it. - `stats-scenarios.tsv`, `stats-steps.tsv`, `dbstats/`: `mysql.innodb_table_stats` (last_update, n_rows) read before and after each scenario and after each step, and the two readings taken just before B. No ANALYZE was run by the measurement.
- `orig/sha256.txt`: the sha256 of the two compose files before B (`zz-lab.ini`, `lab.conf`).

## App and web logs (`logs/`)

The app container's log is very large (the PHP error dumps of the failing requests carry long argument lists): about 1.6 GB for the five scenarios, so the full files are not kept here. `logs/*.dated-lines.txt` keep, byte for byte and in order, only the lines that begin with a date stamp (php-fpm NOTICE and WARNING lines, `PHP Warning` and `PHP Fatal error` lines, and the first line of each Laravel error); the lines that continue a dump (stack frames and argument lists) are left out. `logs/MANIFEST.tsv` lists, for each original log, its bytes, its lines and its sha256, and the bytes and lines kept. `logs/app-after-s-N.at` holds the time each copy was taken (UTC). The web logs (`web-after-s-N.txt`) are kept whole.
